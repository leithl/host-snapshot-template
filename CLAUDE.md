# Notes for AI assistants

Complements [README.md](./README.md). The README is the prose for humans; this file is the directive form for an agent asked to adopt or modify the template. Read both.

## Order of operations (the rule that prevents leaks)

When adopting on a new host, run these in **exactly this order**:

1. Create the private GitHub repo (`gh repo create <user>/<host>-etc --private`).
2. Generate the deploy key as root on the host, register with the repo (`gh repo deploy-key add <pubkey> --allow-write -R <user>/<host>-etc`).
3. Set root's git identity (`sudo git config --global user.email/name`).
4. **Copy `etc/gitignore.secrets` to `/etc/.gitignore` BEFORE `apt install etckeeper`.** This is the load-bearing step — etckeeper's package post-install runs `etckeeper init`, which auto-commits all of `/etc/` against whatever gitignore exists. Anything missing from the gitignore at that moment ends up in commit #1.
5. Audit `/etc/` for host-specific secret-bearing files **not** covered by `gitignore.secrets`; append patterns. See cheatsheet below.
6. `sudo apt install -y etckeeper`.
7. Run the sanity-check from `etc/README.md` step 7 (verify no secrets tracked).
8. Configure `PUSH_REMOTE="origin"`, install `pre-commit.d/50-system-snapshot`, set `/root/.ssh/config` host alias, add remote, commit, push.

**Anti-pattern:** `apt install etckeeper` before `/etc/.gitignore` is in place. Recovery is documented (`etc/README.md` "Recovery if a secret leaked") but costs a GitHub repo deletion, credential rotation, and ~15 minutes of redo.

## Host-specific gitignore cheatsheet

`gitignore.secrets` covers what's common across most Linux servers. Many hosts also have surface-specific secrets the template doesn't preemptively exclude. Common additions by host class:

| Host class | Add to `/etc/.gitignore` |
|---|---|
| Raspberry Pi / SBC | `hostapd/`, `wpa_supplicant/wpa_supplicant.conf`, `wpa_supplicant/wpa_supplicant-*.conf`, `NetworkManager/system-connections/*` |
| Host running a WiFi AP | `hostapd/` (whole dir — `.bak` backups of `hostapd.conf` carry the WPA2 PSK) |
| Ubuntu Pro attached | `apt/auth.conf.d/90ubuntu-advantage` (machine-derived ESM credentials, regenerated by `pro attach`) |
| Any host | `*.bak.*`, `*.bak` (defense-in-depth — backups of edited configs often pre-date redactions) |

Before running `apt install etckeeper`, scan `/etc/` for filenames matching `*pass*`, `*credentials*`, `*token*`, `*.key*`, `*.bak*`, and decide track-or-exclude for each. Err on the side of excluding whole directories (`hostapd/` rather than `hostapd/hostapd.conf`) when the directory's content is uniformly sensitive.

## The hook's final `git add` is load-bearing

`etckeeper-hooks/50-system-snapshot` ends with `git -C /etc add -A system-snapshot/`. **Do not remove.** Etckeeper's `commit.d/30git-add` runs *before* `commit.d/50vcs-commit`; that latter fires git's pre-commit hook, which is what runs `pre-commit.d/*`. So the snapshot hook fires *after* the staging step, and without the explicit re-stage the snapshot updates lag one commit. Discovered + fixed in PR #1.

## Verify-after-change

After any modification to a host's gitignore or the snapshot hook, run on the host:

```sh
sudo git -C /etc ls-files --cached --ignored --exclude-standard
```

Empty output = clean. Any line printed = a tracked file matches the gitignore = a leak waiting to push. Fix: `git rm --cached <file>`, commit, `git reflog expire --expire=now --all && git gc --prune=now --aggressive`, force-push.

## Where to make changes (template vs. host)

- `etc/gitignore.secrets` — cross-cutting patterns (true for every Linux host you'd ever onboard).
- `etc/etckeeper-hooks/50-system-snapshot` — the rebuild-kit refresh hook. Edit the `USERS` list to match local accounts.
- `etc/restore.sh.template` — the rebuild script. Adapt placeholders per host.
- `dotfiles/` — user-level config layer, separate concern from `/etc`.

When deciding template-wide vs. host-specific: if you'd add this pattern on every future host you own → template. Otherwise → that host's own `/etc/.gitignore` (above the `# --- end secret excludes ---` marker so it sits with the human-managed block, not the etckeeper-managed one below).
